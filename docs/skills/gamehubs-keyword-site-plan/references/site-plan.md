# 单站建设方案

为用户指定候选写可审查方案，采用[研究与分档](research.md)的条件。用户只要求方案时可利用标明日期的历史证据，列出建站前须复核项；不能将历史工具值或旧A档当作当前已通过。如果尚未证明竞争切口、持续需求或许可，只交付带阻塞的条件方案，不制造“建议立即建设”。

## 方案必须回答的问题

1. **为什么是这个词。** 主词、市场、数值来源／日期、研究档位、真实搜索意图、主要版本、关键对手及具体可超越点。说明哪些证据已核实、哪些待补，不能靠“同名域可注册”推导能拿走主词流量。
2. **具体做什么。** 可玩首页的核心循环、准确控制、主要设备及真实差异；列首版功能与后续候选。已有对手具备的功能不得当独家差异，避免无意义登录／数据库／多人服务。将改进落到玩家能感知的更快开玩、更少干扰、准确说明、触屏可用、练习反馈等实际能力。
3. **怎样实现。** 首选低成本合法iframe／WebGL／demo；完整许可源码、自研作为备选。分别列发布方、版本、代码与素材／数据依据、嵌入限制、可维护性、运行依赖及未知；无法证明使用依据就保留阻塞。自研不直接复制原版代码、素材、题库或实时数据，不虚称已获授权。
4. **网站与关键词如何对应。** 主词和game／play／online／practice等同意图词优先由一个有用主页承接，不逐变体建站或重复页。how-to-play／strategy／solver／archive等仅在内容或功能真实独立时增加；变体没单独测量就标待验证，不继承或相加主词量。标题以游戏名、玩法和真实控制为主，不虚称官方、联机、原版答案或网络绕过。
5. **内容和域名。** 给出玩法、操作、实际技巧、FAQ及必要相关内容的提纲；800–1500字是有价值内容的编写目标，不灌水或把字数当排名指标。域名建议区分候选、已查可注册、已拥有和已绑定，记录查询日期／渠道；名称、历史风险和使用依据需要核实。查价或列候选不等于购买；无需为方案实际采购。
6. **投入与工作顺序。** 按来源／数据原型、可玩核心、页面、QA、发布及观察拆任务，说明工期和成本假设、外部依赖与停止重估条件。未确认服务或许可费用不报精确总价，不给保证排名或收入预测。历史11方案不作为默认队列，不以长期50–80站目标倒推产量。
7. **怎样判定完成。** 桌面与真实触屏的开始／输入／得分或胜负／重玩，加载失败和外部依赖，准确文案、键盘与窄屏体验；仅缩小桌面窗口不能算真机验收。发布核查HTTPS、主域、canonical／sitemap／robots、真实404、索引状态及统计。新Vercel站按GameHubs规则安装并启用Web Analytics，SDK、项目开启、实际pageview、后台收数分项记录；当前套餐普通启用不含升级或付费附加项。

## 授权与发布后反馈

产物包含建议结论、证据、方案、任务／估算、阻塞和验收条件，篇幅随复杂度调整。用户已授权的下一步继续执行，未授权的购买／发布不由skill自动放行；方案勾选框不能冒充已执行。

在GameHubs内，现有站只改各自正式source对应独立仓库。自定义域默认apex Production、www301，保持路径与查询参数，origin／canonical／sitemap／正式URL一致。发版前检查团队所有项目的重复Git连接，不能因Git Import推荐而重复导入。保留现有noindex及第三方许可待确认项；源码推送、部署、实际可玩、允许索引、搜索引擎收录分别表达。

建议发布后D+7看抓取／索引问题、D+28看查询匹配及游玩、D+56再判断扩张／修正／暂停；这只是观察窗口，不是排名保证，不自动创建定时任务。用GSC曝光／点击及开玩／完成／重玩等实际已采集数据，不把测试PV当自然增长，不把Web Analytics普通pageview当已有自定义游戏事件。没有数据就说明未知并诊断，不能据部署数扩张。
