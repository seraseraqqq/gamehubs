# 游戏单站选词：执行与回填约定

生效：2026-10-29。站主明确要求以附件《游戏复刻单站选词 SOP》为主纠偏；[附件原文副本](KEYWORD_SELECTION_SOP_SOURCE.md)保留不改，本页明确在GameHubs的执行口径。以下顺序与门槛替代旧默认规则；历史批次、人工决定及现有站点状态不追溯改写。本页为手动研究约定，不创建自动化或付费服务。

可用`$gamehubs-keyword-site-plan`调用[挖词与建站方案skill](skills/gamehubs-keyword-site-plan/SKILL.md)。仓库源码用于同步，安装与跨设备要求见[迁移说明](skills/gamehubs-keyword-site-plan/references/portability.md)；skill不自带登录态或API密钥。

## 固定口径与顺序

1. **老词和竞品排名词为主。** 研究资源约70–80%用于Semrush／Ahrefs成熟游戏词、相关词及竞品排名词；20–30%用于findnews等新游戏灵感。比例用于研究规划，不强凑合格数量；新游戏名必须重新验证。优先用站主[免费Semrush镜像](https://sem.3ue.com/analytics/keywordoverview/?db=us)及现有会话；Ahrefs仅在已有可用访问时使用，不因本规则订阅采购。
2. **指标先初筛。** 固定US/en，月Volume≥15,000且KD≤25进入候选，优先Volume≥20,000、KD≤20。记录来源、数据库／时间口径、采集日期及原始返回；工具量是估值，镜像注明非官方核验，不能称真实精确需求或本站可得流量。自部署OpenSEO、DataForSEO可补充核验，费用与凭据按[管理规则](GAME_MANAGEMENT_RULES.md)；来源冲突分别保留，不混用不同工具KD或不同市场数值，未知不作0。
3. **真实Google与版本核对。** 浏览器逐词查看前5–10条自然结果，沿用`gl=us`、`hl=en`、`pws=0`，记录位置、URL、页面形态、具体游戏及试玩观察；广告/视频/AI模块单列。参数不证明物理美国位置，未见完整前十如实记录，不用镜像SERP代替。确认用户主要来直接玩游戏；新闻、同名产品、一次性热点或强站体验完善且无明确切口的词退出默认队列。薄说明、目录、过时内容、广告干扰只作为线索，必须说明具体弱点和我们如何改善；不只因正文少或标题含unblocked就判可超越。
4. **二次分档。** 按下表执行。搜索量大、KD低、开发容易均不能替代真实SERP机会和合法可实施版本；优先低成本合法嵌入，完整许可源码或独立自研可备选，但需先过同样的选词检查并说明成本。技术可嵌入不等于获得许可。
5. **建站前最终确认。** Trends检查US、Web Search过去12个月的持续需求，必要时补90天／5年，排除纯尖峰；稳定老词不必近期上涨。保存窗口、曲线和采集时间；归一化指数不是月量，不同图绝对指数不能直接比较，低采样／失败为unknown。再核实版本、许可／素材／数据、实际运行、维护成本、具体改善、可用域名及玩法／操作／FAQ等结构。沿用附件800–1500字有价值内容的编写目标，不凑字数，不把字数当质量证明；公开文案对应实际功能，不虚称官方、联机或绕过限制。域名可用不代表已购买或获准购买。
6. **全量落盘。** 每轮日期＋设备＋UUID，保留主候选、条件候选、观察、未达标、暂缓、未知和失败。证据进入`research/<date>-<batch-topic>/`，观察导入data/batches，最后validate和generate。研究推荐、人工立项、部署、完整游玩及索引继续分开。原词及同义词归簇但不丢词、不相加搜索量、不按变体重复建站；收入测算不回填本系统。

## 新研究的门槛与优先级

附件同时写了验证KD≤20与“可做”KD≤22；执行解释为≤20主候选、21–22条件候选，避免默默放宽。以下每个可选档均需直接游玩意图、真实SERP可超越性、持续需求、合法可实施版本及具体改善证据。

| 研究结论 | US/en数值条件 | 处理 |
|---|---|---|
| 优先候选 | Volume≥20,000、KD≤18 | 其余条件齐全，低成本合法嵌入优先；仍需独立立项 |
| 主候选 | Volume≥15,000、KD≤20，且不属优先档 | 其余条件齐全才形成可选建议 |
| 条件候选 | Volume≥15,000、20<KD≤22 | 需更明确的竞争机会、差异和成本理由，单列供站主决定，不混入主候选通过数 |
| 观察 | Volume≥15,000、22<KD≤25 | 只通过初筛，不进默认建设队列 |
| 未达标 | 已知Volume<15,000或KD>25，或关键条件明确不成立 | 退出本轮默认新建队列，保存原因和全部记录 |
| 待验证 | 判断所需指标、SERP、趋势、版本／许可等缺失或冲突 | 不当0、不当通过；若已有明确淘汰原因，记录未达标并同时保留其他缺项 |

**KGR／intitle为辅助，不再是默认硬门槛。** 保留现有公式、历史值和看板，不要求逐词补采，不用低KGR替代真实竞争判断。原Volume>10,000／KD<30、后续量>3,000／KD≤30、KGR阈值及强制上涨仅解释各自历史批次，不认证本次新标准。当前看板仍显示旧批次分级，未经新批次复评不能将旧A档当新主候选。

`scripts/finalize-keyword-mining.py`内置2026-10-25的量／KD／KGR／上涨条件及来源日期，仅用于复现原批次，不作为新SOP的分级器直接复用。通用导入、校验、生成命令继续可用；本次没有改写历史脚本或新增自动筛选功能。

附件可选评分权重保留为Volume30%、KD25%、SERP30%、实施难度15%。仅供条件已满足者排序；启用前保存统一评分尺度、各项得分和理由，不直接将原始Volume与KD相加，不编造缺项分数，不以总分抵消未过条件。默认可只分档并写理由。

## 现有项目与扩张方向

后续存量复筛优先重审现有290词及未实施计划，以新批次追加，不删旧词、不改旧评级、不把复用日期冒充新采集。已有上线项目不因门槛变更自动下线；原11项计划仅作历史候选，不再作为默认新开发排队依据。

质量优先于数量。附件50–80站作为长期方向，不是本轮产量承诺或扩张放行条件；先完成已有站正式域名游玩、手机、搜索接入及实绩核查，再逐站决定新增。用GSC曝光／查询／点击及实际开玩／重玩反馈，不以部署数或混有验收的PV证明选词成功。购买、开发、发布、noindex切换仍按独立授权及现有验收条件执行。

历史117词及其完整证据是本轮去重和来源参考，不可将旧指标自动当成新采集。每个词用“原词＋国家＋语言”识别。跨设备使用Git手动同步；未获明确授权时不commit/push、部署、购买资源或联系他人。

## 交付和回填格式

- `batch.json`及其证据：日期、设备、市场、种子/竞品、老词／新词来源规划与实际分布、SOP版本`2026-10-29`、本批criteria、执行状态、来源与缺口；当前schema没有任意metadata顶层字段，新增说明存证据文件并由notes／sources引用，不自行扩展顶层字段。
- `keywords.jsonl`：全部观察，保留原词、国家/语言、各来源指标、qualification、clusterId、evidence、raw和错误/待补原因。格式见[使用说明](USAGE.md)。在assessment／理由中明确主候选、条件候选、观察、未达标及待验证，不为套旧S/A/B/C而掩盖未过条件。数值、SERP、持续性、版本／许可、成本与改善结论可追溯，不能等同人工批准。
- `research/`：保存本轮实际取得的Trends、Google结果、镜像/OpenSEO/API证据；逐来源标明市场、时间与缺项，不保存登录态、凭证、授权头或访问令牌。DataForSEO跨设备可用性采用GitHub Secrets/单独管理解密密钥的密文方案，禁止明文入库；见[凭据规则](GAME_MANAGEMENT_RULES.md#跨设备凭据)。
- AI追加审核时使用actorType=ai、当前expectedHeads和包含该词的basedOnBatches。人工批准/放弃不可被新的AI观察覆盖。未明确批准建设，不自动创建站点或仓库。
- 通过现有命令导入和汇总，不改写历史批次：

```sh
python3 scripts/hub.py import /path/to/batch.json /path/to/keywords.jsonl
python3 scripts/hub.py validate
python3 scripts/hub.py generate
```

相同ID不同内容会拒绝覆盖；修正数据应使用新批次并引用原批次。单条坏行保留errors.jsonl，其余正常行照常入池。若校验报错，记录问题并修正可修部分，不把缺失结果改成通过。
